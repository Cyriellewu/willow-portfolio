Oracle OS

A reflection app built on Tarot, I Ching, BaZi, and Astrology, with one rule: code generates every symbol, and the language model is only allowed to interpret. The boundary is in the architecture, not in a prompt.

Role
Product architect and full-stack implementer
Stack
TypeScript, Supabase, Vercel
Engines
Tarot (78 cards), I Ching (64 hexagrams), BaZi, Astrology
Source
github.com/Cyriellewu/oracle-os

Problem

Fortune apps over-promise certainty and blur the model's randomness into a "reading". I wanted the opposite: a calm reflection tool where the symbolic material is deterministic and auditable, and the model's role is bounded and visible to the user.

What I built

  • Four rule-based engines that produce the symbolic state in code, plus a council mode that runs several lenses in parallel and synthesizes them.
  • LLM calls isolated to reflect, chat, and council endpoints. Prompts are externalized under version control, inputs are validated at the API, and a mock-LLM fallback keeps the demo working without API keys.
  • A journal loop: each day's reflection is stored, recurring motifs are extracted, and the next day's prompt is personalized from them.
  • A daily reflection and a food draw that use no model at all.

Safety

Medical, legal, and financial prompts are redirected before they reach a model. These are product-level guardrails alongside the externalized prompts and API validation, not a claim of comprehensive safety.
